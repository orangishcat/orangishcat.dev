I added Schoology notification scraping via internal API and cookies. Unfortunately Schoology API does not expose notifications for whatever reason, so this is what I had to do.

I'm using two routes: `https://<subdomain>.schoology.com/home/notifications?filter=all`, which returns HTML, and `https://<subdomain>.schoology.com/iapi2/site-navigation/notifications`, which returns JSON.

The former is much more reliable as it gives full information about every notification:
![[./Attachments/Pasted image 20260912090131.png]]
The embedded HTML has the course name, course ID, and resource ID's all easily extractable from the HTML used to build the notification section. The `# other item(s)` text opens a popup of the remaining items, but as it turns out the returned HTML contains information for those remaining items as well.

This required installing a new `scraper` library, and I set up some basic DOM parsing to fetch notification info.

The latter route is much more limited, and is mainly used as a fallback.
![[./Attachments/Pasted image 20260912090449.png|128]]

The links are inconsistent, it only shows the top 5 notifications, and the time has to be guessed based on the formatted string.

Total time: 4.5 hours
