I've wanted to do this for like 3 years (ever since I started middle school), but I had no idea what was doing and also kinda never bothered.

Today was mostly an exploration day that led me to settle upon the below plan.

Plan: 
- Stack: Slint with Rust, wry for browser stuff
- Session cookie login using wry as browser + API key fallback
	- This is because some internal schoology endpoints (e.g. notifications) have no equivalent in the API
	- Both are ratelimited
	- Why tf are notifications not exposed in the API? Why???
- Roadmap
	- Index all your courses
		- Don't store actual files on filesystem unless explicitly enabled; instead just store the internal asset url which can be fetched with session cookie auth (ANOTHER REASON WHY SESSION COOKIE AUTH IS IMPORTANT)
		- Main reason for indexing is to do super fast fuzzy file/assignment search
			- Future: If supported file type (PDF/docx/pptx), we can even temporarily download to analyze the content of it to be used in search
	- Use notifications as a source of updates; only download changes since last refresh unless something is corrupted
- Name ideas:
	- folms (acronym for Fast Open Learning Management System)
		- I am pretty bad with making names so I just chose some random letters that aren't heavily taken or mean anything weird
		- This is heavily subject to change if I think of something better
