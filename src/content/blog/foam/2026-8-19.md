Finally made some progress in Schoology course scraping. 

I had the internal cookie-based scraping already set up, but I didn't want to make two routes at once before I even had a UI. So I just went with API only for now. Internal cookie-based scraping is still necessary as there is no Schoology notifications API, yet it is exposed in some very nice formatting as an internal endpoint. 

For example, new course material posted:
```json
{
  "data": [
    {
      "type": "course_materials_add",
      "sentence": "%s posted %s and %s",
      "viewed": true,
      "created": "Today at 3:33 pm",
      "more": "",
      "realm": "course",
      "realmId": "<realm id>",
      "args": [
        {
          "id": "<id>",
          "title": "<course name>",
          "type": "s_content_course_section"
        }
        // 1 more, matching the number of %s in the "sentence" parameter
      ]
    }
  ]
}

```

New grade added:
```json
{
  "data": [
    {
      "type": "grade_add",
      "sentence": "A new grade was posted for %s and %s",
      "viewed": true,
      "created": "Yesterday at 1:02 pm",
      "more": "",
      "realm": "user",
      "realmId": "<realm id>",
      "args": [
        {
          "id": "<item id>",
          "title": "<assignment id>",
          "type": "s_content_grade_item"
        },
        // 1 more matching %s count in the "sentence" parameter
      ],
      "iconUrl": null
    }
  ]
}
```

Each API route is coerced into a serializable type for code usage, then dumped as raw JSON when saved into the filesystem, something like this:

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct Link {
    #[serde(default, deserialize_with = "string")]
    pub id: String,
    #[serde(default)]
    pub title: String,
    #[serde(default)]
    pub url: String,
    #[serde(default, deserialize_with = "integer")]
    pub course_fid: i64,
    #[serde(default, deserialize_with = "integer")]
    pub available: i64,
    #[serde(default, deserialize_with = "integer")]
    pub published: i64,
    #[serde(default)]
    pub attachments: Attachments,
    #[serde(default, deserialize_with = "integer")]
    pub display_inline: i64,
}
```

Another thing I learned: the `?` operator in Rust. Makes returning `Result`s through nested chains of API calls much easier.

```rust
// Returns the error object as a Result if the call fails, does nothing otherwise
let response: Page = api_get(url)?;
```

It feels like a much more elegant solution than Golang's errors as return values.

```go
f, err := os.Open("filename.ext")

// you have to do this for pretty much every function call, so your code is just filled with these err != nil if statements
if err != nil {
    return "", err;
}
```

Now this does mean that I have to put question marks everywhere because absolutely everything seems to return a `Result`, but I think it's a nice pattern.

And it also reminds me of Java's `Optional`s, which are great but would contribute to garbage collector overhead as each `Optional` is an immediately discarded object.

```java
var thing = Optional.of(nullableFunction());
return thing.orElse("null");
```

It's a bit of a change from the try-catch exception handling I'm used to, but it works, and it might even be a bit more concise.
